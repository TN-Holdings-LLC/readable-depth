# readable-depth

How deep a circuit stays readable on a raw quantum device, per problem family. TN Holdings.

The records behind every number here are the declared device tests in
[TN-Holdings-LLC/psf-os-lab-notebook](https://github.com/TN-Holdings-LLC/psf-os-lab-notebook) (formerly TOQB).
This repository holds the definition, a small scorer, and snapshots of the boundary table and the classical-reach
ledger built from those records.

## Definition

A run is **raw**: no error mitigation, no dynamical decoupling, no twirling; placement reads only the coupling graph,
the basis gates and which elements have failed (no calibration error rates). It is **declared** (circuits, depths,
answers' hash, verdicts, prediction) and pushed before the device's calibration is fetched; the exact answers are
sealed until the verdicts.

- **READS**: the mean squared error of the device values against their exact values is at most half the mean square
  of the exact values, `MSE <= mean(exact**2) / 2`. Returning zeros everywhere gives `MSE = mean(exact**2)`; READS
  asks that at least half of the signal's squared size survives.
- **AGREES**: counted per value, `|device - exact| <= 0.05` for per-qubit `<Z>`.
- **Readable depth** of a family (one problem, one device, one day, depths declared before the run): the largest
  declared depth that READS, with the first depth that does not read beside it. Depth is counted in CZ layers of the
  compiled circuit (also given in steps of the problem).
- Controls in every job, reported beside and never used to correct: floor (prepare and measure), mirror (the compiled
  circuit, a barrier, then its inverse), ring sentinel.

## What the records say so far (see `data/boundary_2026-11-13`)

- Within one family, depth decides: 1D Hubbard (U 4) on ibm_fez, 2026-11-11, read at 48 CZ layers (4 steps) from 40
  to 120 qubits and did not read at 72 (6 steps).
- Across families it does not: other records read up to 187 CZ layers (figure c). Where the boundary lies depends on
  how fast the exact signal shrinks with depth.
- Each row is one device on one day. Nothing here is a hardness claim; every answer was computed classically
  (`data/classical_reach_ledger.md` records with what, and how long).

## Use

```bash
python -m readable_depth.score card CARD.json     # {"z": [...], "exact": [...]}  -> MSE, mean square, READS, AGREES
python -m readable_depth.score depth ROWS.json    # [{"family", "depth", "verdict"}, ...] -> readable depth per family
python -m pytest tests                            # includes a check against a committed device record
```

Needs Python 3 and numpy.

## Contents

- `readable_depth/score.py`: the rule and the per-family depth.
- `data/boundary_2026-11-13/`: the boundary table with the 2026-11-12 results added (262 judged units of 31
  results: Trotter step sizes on ibm_fez, Ohm 6 cycles on ibm_fez and ibm_kingston, the XX chain of 91 qubits on
  ibm_fez; figures a-c), generated by `notes/boundary_2026-11-13/boundary.py` in psf-os-lab-notebook at commit
  460126ec. The Ohm rows are judged on M per circuit (a sum over 20 qubits), not on per-qubit Z.
- `data/boundary_2026-11-12/`: the earlier snapshot (234 judged units of 27 results), generated by
  `notes/boundary_2026-11-12/boundary.py` at commit e1ad481; kept as it was.
- `data/classical_reach_ledger.md`: how far the classical check reached, per problem (same commit).
- `tests/`: the rule on hand-made cases, and the 2026-11-12 Trotter-step record (ibm_fez) recomputed.
